## 1. 聊天与成长数据联动（让 AI 知道你家宝宝）

**状态**：⏸ 未开工 · 2026-10-17 记录
**优先级**：中 —— 建议排在下面两件事之后：
① 成长模块的 `error` 没有任何组件渲染（加载失败时界面毫无提示）
② evalflow 端到端评测还没真跑过一轮（3001 那个被测实例已就绪）

### 现状（2026-10-17 查证，不是推测）

聊天链路上**完全没有**用户录入的宝宝数据：

| 检查点 | 结果 |
|---|---|
| `ChatRequest` 字段（`app/models/chat.py:10`） | 只有 `message / history / session_id / file_id`，**没有 childId** |
| `_build_messages` 的 `profile_text` 参数（`app/services/chat_service.py:70`） | 参数和分支都在，但**第 237 行调用时没传** → 恒为 `""`，那个 `if` 永远不执行 |
| 聊天链路里搜 `growth` / `child` | `chat_service.py`、`services/rag/*` 里**一处都没有** |
| 成长数据存在哪 | `data/growth.db`（独立 SQLite），只由 `/api/growth/*` 读写 |
| 前端聊天组件 | `components/chat/*`、`hooks/useChat.ts` 里没有任何 growth/child 引用 |

界面走的是 `/api/chat/stream`（`client/src/services/api.ts:207`）。

### ⚠️ 一个查证时发现的意外

README 的「待实现功能」表里，**跨会话记忆**标的是 ✅ 已实现 —— 这**不准确**：

- `app/services/memory/user_profile.py` 那套（`extract_profile` / `save_profile` / `get_profile`）确实写好了
- 但它**只被 `/api/agent/unified` 调用**（`services/agent/unified.py:243/280/287`）
- 而**前端根本不调任何 `/api/agent/*` 端点**（`client/src/services/api.ts` 里搜不到）
- `ensure_collection` 更是从未被调用

所以：机制存在，但**界面上用不到**。README 那一行已同步修正，并指向本文。

这件事对本条的启示：**要做的不是"从零加一个画像"，而是"把已有的画像机制接进主聊天链路，并让它包含成长数据"**。`profile_text` 那个参数就是为这件事留的口子。

### 为什么值得做

1. **这是这个 App 的产品命题，不是锦上添花。** 育儿建议强依赖月龄 ——「宝宝不爱吃奶」在 3 个月（生理性厌奶）和 2 岁（行为性挑食）是两个问题、建议相反。
2. **检索解决不了这件事。** `rag_medical` 那 3633 条是不分年龄的通用知识，检索"厌奶"只会返回一堆要自己挑的通用内容。**月龄这个维度只能来自用户录入的数据。**
3. **成本主要在设计，不在实现** —— 钩子已就位。

### 已定的方案（最小版）

**只注入"档案 + 最近一条记录 + 记录日期"，不要一上来就全量。**

```
【当前宝宝】小元宝，5 个月 3 天，男
【最近一次记录】2026-09-10（37 天前）：身高 70cm、体重 8.5kg、睡眠 15h、尿布 9 次
```

**不要注入**：
- 全部历史记录（会持续增长，token 成本不可控）→ 要趋势就另做摘要
- `GrowthRecord.notes`（用户写给自己的自由文本）—— 吃 token 且不可控，可能夹带无关内容干扰指令
- `GrowthAnalysisResult`（summary/suggestions/warnings）—— 那是**另一次 LLM 调用**的产物，每轮聊天都做太贵，要注入必须先加缓存

### 三个必须处理的边界

**① 数据会过期 —— 最大的坑。**
用户录的是 6 个月时的数据、3 个月后来问，模型拿着"6 个月"回答，**比不知道更糟**：它会自信地给错月龄的建议。
→ 注入时必须带**记录日期**，并在 prompt 里写明「该数据是 N 天前的；若问题依赖当前月龄，先向用户确认」。
**这一条不做，宁可不接这个 feature。**

**② 别让模型自己做百分位判断。**
LLM 算百分位不可靠，而 WHO 曲线要按**性别 + 精确月龄**查表才有意义。
查证结果：后端**没有**百分位计算（只有 `app/models/growth.py:16` 一句范围注释；前端画图用的是接口返回的 `ageMonths`）。
→ 两个选项：(a) 只注入原始数字 + 明确告诉模型「不要据此做生长评估，需要评估请引导用户去「分析」页」；(b) 先把百分位算到后端再注入 —— **这才是真做对**，但那是独立工作量。

**③ 必须按 `user_id` 过滤。** 否则串号读到别人的宝宝。`app/core/auth.py:51` 专门强调过这点。

### 待决问题（下次开工先回答这几个）

1. `childId` 从哪来？聊天界面目前**没有"当前宝宝"的概念** —— 用户在成长页选了宝宝，这个选择要不要提升成全局的？还是每次聊天时现选？还是取"最近看过的那一个"？
2. 多宝宝怎么办？档案里可能有 2 个以上宝宝（`user_alice` 现在就有 2 个）。
3. 注入的画像要不要显示给用户看？（决定要不要在聊天界面加一行"已知宝宝信息"的提示，以及用户能否纠正）
4. 和 `extract_profile` 那套怎么共处？**建议分开**：那是从对话猜的、模糊易错；成长数据是用户**明确录入**的结构化事实。两者都进 `profile_text` 时要能分清来源与可信度。
5. 没有录入任何成长数据时怎么办？——应该静默降级，不能报错也不能编。

### 验收方式（别只看"接上了"）

1. **真实对话验证**：录一个宝宝 → 聊"宝宝最近不爱吃奶" → 回答里应出现该宝宝的月龄，且建议与月龄匹配
2. **反例验证**：把记录日期改到 3 个月前 → 模型应主动确认"这个数据是 X 前的，现在宝宝多大了？"而不是直接按旧月龄回答
3. **无数据验证**：换一个没录宝宝的账号 → 回答应与现在完全一样，不能报错也不能凭空提宝宝
4. **多租户验证**：`dev-key-bob`（无宝宝）不能看到 alice 的宝宝信息
